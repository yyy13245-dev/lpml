## ⚡ 快速开始

1. 从本仓库的 Releases 页面下载发布包；若暂未提供，请按下方命令从源码编译。装好后可在「设置 → 在线更新」里手动检查新版本，不必重新下载整包。
2. 解压到任意文件夹，双击 `LPML.exe`。**首次启动会显示《用户协议与免责声明》**，阅读并同意后进入主界面。
3. 在「下载 → 安装游戏」选择版本，装好后在「开始游戏」页选择实例并启动。

仓库内不含游戏文件、账户凭据与二进制发布物。运行时数据（配置、账户、日志、缓存）都写在启动器目录内，并已在 `.gitignore` 中排除。

## ✨ 主要特性

### 界面与动效
- 「开始游戏」按钮**全局悬浮在右下角**，任何页面都可见：在其他页面时点击跳到开始游戏页，
  已在开始游戏页时直接启动（文案随页面在「开始游戏 / 启动游戏」间切换）
- **自定义背景图**：设置 → 外观，确认后复制到 `LPML\backgrounds\`；
  支持 png / jpg / jpeg / bmp / **gif（可播放，逐帧还原原始延迟）**，可调透明度（默认 60%）与填充方式
- **自定义标题**：启动器自己的窗口标题（失焦即生效）、MC 游戏窗口标题（走客户端原生 `--title`）
- **多实例并存**：可以同时启动多个游戏。有实例在跑时右下角出现「⏹ 结束游戏」，点开是展开板，
  选中哪个就结束哪个；启动器日志按实例名区分各自输出。
  首页实例下拉框会即时包含新建的实例，直接选中即可切换

- Mica / Acrylic **毛玻璃**窗口（DWM 系统背景，失败时自动回退为「背景图 + 高斯模糊」方案）
- 无边框自绘标题栏、圆角、深色/浅色/跟随系统主题、强调色自定义
- **拉伸动效**：卡片 / 按钮悬浮缩放、按下横向拉伸回弹、列表逐个入场、页面切换淡入上浮
- 所有动效可在「设置 → 外观」一键关闭或调节时长
- **性能模式**（标准 / 流畅）：流畅模式关掉毛玻璃与半透明合成、把悬停反馈改成瞬时切换、
  只保留最轻量的动画，适合低性能设备；也可以用启动参数 `--smooth` / `--standard` 切换
  （会写进配置，以后一直生效）

### 国际化（i18n）
- **语言包分离**：全部界面文本放在 `src/LPML.App/Locales/*.xaml`（ResourceDictionary），代码里**零硬编码文案**
- **引用方式**：XAML 用 `{DynamicResource String.模块.项}`，C# 用 `Lang.T("...")` / `Lang.F("...", args)`，Core 层用 `L.T` / `L.F`
- **运行时切换**：设置 → 高级 → 界面语言，换语言包后界面**立即刷新**，无需重启（导航树等代码生成的部分自动重建）
- **内置语言**：简体中文（zh-CN）、English（en-US），各 **1530 条**词条，键名一一对应
- 键名规范 `String.<模块>.<项>`，例如：
  - `String.Settings.Title`、`String.Account.LoginSuccess`、`String.Msg.Download.Installing`
- 新增语言只需复制一份 `Locales/zh-CN.xaml` → 改文件名与值 → 在 `LauncherLanguage` 加一档
- `Lang.F` 支持 `{0}` `{1}` 占位符，语序可随语言调整；Core 层文本由宿主注入 `L.Provider`

### 内容浏览（Modrinth）
侧边「实例 → 内容（Modrinth）」，四个 Tab：**模组 / 资源包 / 光影 / 整合包**。
只接 Modrinth，不接 CurseForge——后者要申请 API key、有调用限制且条款更严。

- **下载路径自动分流**：模组→`mods/`、资源包→`resourcepacks/`、光影→`shaderpacks/`、数据包→`datapacks/`
- **默认推荐当前实例**：选中实例后，搜索筛选与版本分组默认用它的 MC 版本与加载器；
  可手动在筛选栏改（改了就以筛选结果为准），也可取消「跟随当前实例」
- **版本两级选择（模组）**：先选 **MC 版本**（下拉框，推荐项排最前并标「（推荐）」），
  再选该 MC 版本下这个模组的**具体版本**（按发布时间倒序，显示发布通道与支持的加载器）。
  同一个模组的不同 MC 版本各自独立，切换 MC 版本即可看到那一版下的全部模组版本
- **加载器可切换**：Forge / Fabric / NeoForge / Quilt 各版本都能选，默认落在当前实例的加载器
- **依赖展示**：列出必需/可选/不兼容/已内置依赖，点一下跳到那个项目
- **跳转网页**：项目页、Modrinth 首页
- **整合包**：不推荐版本、不显示依赖（整合包没有依赖），安装时**自动新建实例**而不是覆盖现有实例

**光影前置检查**：下载光影前会先扫描实例的 `mods/`，确认有没有 Iris / Oculus / OptiFine。
没有就在详情页顶部给出提示条和「查找 XXX」按钮（一键跳到 Modrinth 搜对应加载器）——
没装加载器，shaderpacks 里的光影不会被读取。原版实例会提示先装 Fabric/Forge。

### 整合包导入（zip）
支持 **zip 格式的整合包**。导入前会先探测格式并弹窗确认，不会盲解压：

| 格式 | 识别依据 | 模组能否自动装 |
|---|---|---|
| **Modrinth** `.mrpack` | `modrinth.index.json` | ✅ 联网下载 |
| **MultiMC / Prism** `.zip` | `mmc-pack.json` | ✅ 模组就在包里，无需联网 |
| **HMCL 导出** `.zip` | `hmcl.modpack.json` | ✅ 模组就在包里 |
| **通用 zip** | `.minecraft/` 目录结构 | ✅ 整包解压 |
| **CurseForge** `.zip` | `manifest.json` | ⚠️ 见下 |

**CurseForge 包的限制（重要）**：CF 的 `manifest.json` 里只有 `projectID` / `fileID`，
**无法构造下载地址**——必须调 CF API，而 CF API 要申请 key。既然不接 CF，这部分就装不了。
启动器的处理是：
- `overrides/` 里的文件**照常自动解压**（配置、资源包、脚本都能用）
- MC 版本与 Forge/Fabric 版本**正常读取并写入实例**
- 把 N 个拿不到下载地址的模组**列成清单**告诉用户，提示放进哪个 `mods/` 目录，并可一键打开项目页

也就是说 CF 包能导入"半个"——框架和配置齐全，模组需手动补。这比直接报个错要有用得多。

**安全**：所有解压都做 Zip Slip 校验，含 `../../` 的条目会被拦截并记日志，不会写到实例目录外。

### 命令行模式
不带参数双击 → 正常图形界面；带 `--cli` → 命令行模式（不创建窗口）。

> **首次使用同样要同意协议**：命令行模式第一次启动（包括 `--list` / `--help` 等一次性查询）会完整显示《用户协议与免责声明》，只有输入 `是` / `我同意` / `同意` / `yes` 才会继续；输入其他内容、直接回车或无法读取输入时，命令行会直接退出。同意状态与图形界面共用，记录在 `launcher.json` 的 `AcceptedAgreementVersion`，不会上传。

```
LPML.exe --cli [选项]

选项
  --instance, -i <名称/ID>   指定实例（支持模糊匹配）
  --version,  -v <版本ID>    直接按版本启动，不经过实例
  --account,  -a <用户名>    指定账户
  --arch <架构>              下载 Java 时指定架构（x64 / x86 / arm64）
  --after <keep|hide|exit>   启动 MC 后启动器行为
  --yes, -y                  非交互，直接用推荐架构

查询
  --list, ls       列出实例      --list-versions  列出已安装版本
  --list-accounts  列出账户      --list-java      列出 Java（含 JDK/JRE）
  --help           帮助
```

- **不带任何选项 → 启动器 shell**：单独打开一个控制台窗口，底部常驻提示只保留 `help`。
  输入 `help` 查看完整命令表（实例、账户、版本安装、模组、下载、Java、设置、文档等约 50 条命令），
  常用的是 `ls` 列实例、`launch <实例名>` 启动游戏、`quit` 退出、`clear` 清屏。
  游戏启动后同一个窗口切换为游戏 REPL，输入行继续可用。
  `--list` / `--help` 等一次性查询不另开窗口，结果直接输出在当前 cmd 里
- **中文不乱码**：控制台代码页统一设为 UTF-8（65001），退出时还原父 cmd 的原代码页
- **日志打到控制台**：启动器自身日志按 `[时间] [级别] [来源] 消息` 格式输出；
  REPL 运行时改投日志区，不会冲掉上下分区
- **转发 MC 日志**：游戏启动后，MC 进程的 stdout/stderr 实时转发到控制台，退出时打印退出码
- **三种输出形态**：
  | 参数 | 形态 | 说明 |
  |---|---|---|
  | （默认） | **交互式 shell + REPL** | 游戏前 shell、游戏中 REPL，底部固定输入行 |
  | `--log-only` / `--log` | 仅日志 | 日志持续刷屏，不接受输入（Ctrl+C 结束） |
  | `--input-only` / `--input` | 仅输入 | 日志只写 `logs\cli\`，控制台只剩输入行 |

- **REPL 命令**：`help` / `status` / `java` / `clear` / `stop` / `kill`，
  其余原样转发给游戏进程（服务端有效）。Ctrl+C 等同 `stop`
- REPL 靠 ANSI 转义码分区，Windows 需 10 1511+；输出被重定向时自动退化为普通逐行输入
- **跨芯片架构不硬编码**：下载 Java 时列出远程索引里真实存在的架构供选择，
  推荐项依据**你已有 Java 自报的 os.arch**（而非本机架构），
  因为 x64 机器上可能跑 32 位 Java、Apple Silicon 上可能跑 Rosetta 转译版

### Java 管理
- **显示 JDK / JRE**：列表每项标明类型（`JDK 21 · Eclipse Temurin · 64位`），
  判定依据是 bin 目录下有无编译器 `javac`，以及目录名是否带 `jre`
- **同一版本有 JDK 和 JRE 时默认用 JDK**，可在设置里改成「优先用 JRE」
  （Java 9 之后官方不再单独发行 JRE，通常只会有一个）
- **启动失败自动换 Java 重启**：某个 Java 失败后自动换**同版本**（通常是 JDK↔JRE 互换）或**更高版本**再试，
  同版本优先（跨大版本风险更高）。**不会退到低版本**——低版本本来就跑不动，换上去只会再失败
- **也可选「不重启并抛错」**：设置 → Java → 启动失败时，选「不重启，直接报错」，
  最多尝试次数可设 1~5（默认 3）
- **启动 MC 后的行为**：保持原状（默认）/ 最小化 / 直接退出，实例可单独覆盖全局设置
- 重试成功后状态栏会提示「前 N 个 Java 启动失败，已改用 X 启动成功」；
  实例设置 → 诊断 里能看到上次实际用的是哪个 Java
- **Java 列表**：设置 → Java，列出所有已发现的 Java（版本 · 发布者 · 架构 · 来源 · 状态）
- **添加 Java**：选择 java 可执行文件（Win `javaw.exe`，Linux/macOS `java`）后自动识别版本、名称、发布者，
  并**自动同步同一个 JDK 根目录及隔壁目录的其他 Java**（选一个 jdk-21，同目录的 jdk-8/17 一起进来）
- **扫描来源**：`同步 PATH`（PATH + JAVA_HOME，快）/ `全量扫描`（+ 常见安装目录 + 游戏 runtime）
- **多 Java 自动选择**：按版本要求自动挑最合适的（1.16→8、1.17→16、1.18→17、1.20+→21、26w+→25），
  精确匹配优先 → 更高版本 → 64 位回退；也可「设为固定」锁定某一个
- **发布者识别**：Temurin / Zulu / Corretto / Dragonwell / Kona / Semeru / BiSheng / GraalVM / Liberica / Oracle / OpenJ9 / JetBrains 等
- 列表持久化在 `LPML\config\javas.json`，可改名、验证、移除（移除只出列表，不删磁盘文件）
- 首次启动若列表为空且开启了自动探测，会自动同步 PATH 里的 Java

### 实例设置（独立页面）
- 左侧章节导航 + 右侧面板：**概览 / 游戏设置 / 模组管理 / 版本隔离 / 高级参数 / 诊断与文件**
- 每项都是「实例级覆盖」，`null` = 跟随全局；只有勾选覆盖才写进 `instance.json`
- 覆盖项：Java 路径、自动/手动内存、窗口尺寸、全屏、窗口标题、进程优先级、启动后行为、
  服务器直连、JVM / 游戏参数、环境变量、**启动前命令**（`{path}` `{verpath}` `{java}` `{name}` `{version}` 占位符）
- **隔离模式**（可覆盖全局）：`仅用户数据` / `完整隔离`，见下方「实例隔离」章节
- **文件夹已移到独立页面**：侧边「实例 → 文件夹」。文件夹决定当前能看到哪些实例；
  实例设置里不再切换文件夹，避免把实例挂到一个没有实际文件的目录
- **无实例时的空状态**：没有安装任何实例时，所有设置面板整组置灰，顶部给出引导提示和「去下载中心」按钮
- 诊断：完整性检查与一键补全、上次启动信息、启动命令预览、日志 / 崩溃报告 / 启动器日志入口
- 模组管理内嵌：扫描实例 mods 目录，一键启停（`.jar.disabled`）、添加、删除

### 实例隔离
隔离数据放在 **`.minecraft\instances\<id>\`**（不是启动器目录）——整个 `.minecraft` 拷走就带走一切，方便迁移。
旧版本存在 `LPML\instances` 的数据会在启动时自动搬过来。

两种模式，**全局可设、实例可单独覆盖**：

| 模式 | 版本文件（versions/libraries/assets） | mods/saves/config | 特点 |
|---|---|---|---|
| **仅用户数据**（默认） | `.minecraft`（多实例共享） | 实例目录 | 省空间 |
| **完整隔离** | 实例目录 | 实例目录 | 整个目录拷走即可迁移 |

- 切换入口：**设置 → 路径 → 隔离模式**（全局）、**实例设置 → 隔离**（单个实例，可选「跟随全局」）
- **互相迁移**：两种模式之间可一键搬移，同卷走硬链接（零拷贝、不额外占空间），跨卷才复制
- 实例级覆盖后，该实例不再跟随全局设置

### 实例文件夹
可以创建任意多个**实例文件夹**，每个都是一套完整的游戏目录结构
（`versions / libraries / assets / mods / saves / config / resourcepacks / shaderpacks`）。

- 路径支持**绝对 / 相对（相对启动器根目录）/ 环境变量**（`%USERPROFILE%\...`）
- **独立入口**：侧边「实例 → 文件夹」页里新建 / 删除 / 设为当前文件夹，并列出该文件夹里
  真实存在的实例与版本（按物理目录扫描，不读共享 `.minecraft` 的缓存）；新建文件夹不会改动任何现有实例
- **名称查重按文件夹**：不同文件夹允许同名实例，不再被别的文件夹里的同名挡住
- 实例可绑定到某个文件夹，也可直接指定目录（直接指定的优先级更高）
- 目录解析优先级：`DirectoryOverride` → `FolderId` → 隔离目录 → 默认 `.minecraft`
- 支持**在指定文件夹里下载安装**游戏文件，而不只是装到全局 `.minecraft`
- 每个实例目录下会写一个 **`lpml.json`**，记录该实例的名称 / 版本 / 加载器 / 隔离模式，
  跟着目录走 —— 拷给别人或恢复到别的机器上时，这些设置一起过去

### 启动流程
点「启动游戏」后弹出进度窗，**直到游戏进入主界面才关闭**（不再"提示启动成功但窗口没出来"）：

```
① 处理依赖   → 缺多少文件、进度、速度、剩余时间
② 正在登录   → 正版走微软验证 / 外置走 Yggdrasil / 离线直接通过
③ 准备启动   → 拼接 JVM 参数与 classpath
④ 正在启动中 → 实时显示 MC 日志最后几行
⑤ 关闭       → 检测到主界面日志（Reloading ResourceManager / OpenAL initialized / Done 等）才关
```

启动期间**启动按钮、实例下拉框、静音按钮一起置灰**，`finally` 保证无论成败都恢复。
文件缺失会给出明确原因（缺 JSON 还是缺 jar、文件实际在哪个目录），不会再用误导性的「Java 0」。

**同一时刻只允许一个游戏**：游戏运行时，右下角悬浮按钮和开始游戏页的启动按钮都会变成
「⏹ 关闭游戏」，点一下立即结束游戏进程（含子进程）；此时再点任何启动入口都只会提示「游戏正在运行」，
不会开出第二个进程。启动器关掉再打开，如果上次的游戏还在跑，也会认出它并保持这个状态。
用户主动关闭不会弹崩溃提示，日志里记为「用户主动关闭了游戏」。

### 静音模式

### 下载引擎
- **多任务并发**（可调 1~128）+ **单文件多线程分段**（HTTP Range，默认 8 段，**2 MB 以上启用**）
- **按文件大小自适应并发**（默认开启）：MC 全是小文件，所以小文件多开、大文件收窄
  ```
  30 KB 库文件 → 并发 48      2 MB 资源 → 并发 32
  5 MB 以上    → 并发 8（大文件靠分段吃满带宽，多开只是互相抢）
  ```
  三项都可在「设置 → 下载」手填，也能整个关掉退回固定并发
- **平缓启动**：并发不是一把全开，而是从 4 个起、每 240ms 递增，**1.7 秒爬满**。
  避免瞬间几十个 TLS 握手把老机器卡住、也避免被镜像源判定为刷流量
- **失败率自适应**：叠加在体积基准之上，成功率低就降、高就回升，偶发一次失败不会一路压到底
- 断点续传（分片 `.part` 续写）、SHA1 + 大小校验、服务端不支持 Range 自动回退单线程
- **403 / 404 自动换源重试**：镜像没有这个文件就换下一个（最后回退官方地址，一定有文件）——
  对着同一个地址重试是没有意义的，这是过去"装不上版本"的主因
- **429 单独退避**：真限流时按 1.2s × 次数退避，并给出人话提示
- 全局限速（KB/s）、代理、自定义 UA、可选的「忽略证书错误」

### 下载性能
- **HTTP/2 多路复用 + 连接池**：`SocketsHttpHandler`，`MaxConnectionsPerServer=128`，
  空闲 2 分钟 / 存活 10 分钟，小文件不再每次重新握手
- **DNS 预热**：开跑前先把镜像域名解析一遍填进缓存
- **本地库复用（版本目录即缓存）**：扫描已有游戏目录按 SHA-1 建索引（持久化，靠大小+修改时间判断失效），
  装新版本时命中就**硬链接**过去 —— 零拷贝、不额外占磁盘，也没有独立缓存目录。
  可在设置里添加第三方启动器的目录（如 HMCL / 官方启动器）作只读复用源
- **阶段计时**与**带宽统计**：解压 natives、构建清单等各阶段分别记耗时；
  下载结束输出平均 / 峰值速度，方便判断有没有跑满带宽

### 绿色运行（重点）
- 根目录 = 程序所在目录；**不写 C 盘、不写注册表、不写 AppData**
- 发布产物保持 **.NET 默认的多文件布局**，一次性摊平在根目录，不做人工整理：
  ```
  <root>\
    ├─ LPML.exe
    ├─ LPML.dll / LPML.Core.dll
    ├─ *.dll（WPF 与运行时依赖）
    ├─ LPML.runtimeconfig.json / LPML.deps.json
    │
    ├─ .minecraft\                 # 运行时生成 · 标准官方结构，PCL / HMCL / 官方启动器通用
    │   ├─ versions\ libraries\ assets\ saves\ mods\ runtime\
    │   └─ instances\              # 实例隔离数据（跟着 .minecraft 走，方便迁移）
    │        └─ <id>\ lpml.json    # 每个实例自己的本地配置
    │
    └─ LPML\                       # 运行时生成 · 启动器自身的数据
        ├─ config\                 # launcher.json / instances.json / folders.json / library-index.json
        ├─ accounts\               # accounts.json（默认位置，可切到本机用户目录）
        ├─ cache\                  # 分片 temp、安装器、整合包、更新暂存（update-*）
        ├─ backgrounds\            # 自定义背景图
        └─ logs\                   # lpml.log + oldlog1~5.zip（启动时自动归档，最多 5 份）+ update.log
  ```
- 即：**发布文件在根目录，运行产生的数据在 `LPML\`，游戏数据在 `.minecraft\`（PCL / HMCL 通用格式）**
- 升级时若检测到旧版散落在根目录的 `config` / `logs` / `cache`，会自动迁移到 `LPML\` 下
- **日志自动归档**：启动时若 `lpml.log` 有内容，打包成 `oldlog1.zip` 并把已有归档整体后移一位，
  第 5 份（最旧）自动删除 —— 所以 `oldlog1` 永远是上一次的日志
- **日志带编号**：每条日志形如 `[#0042] [22:05:42] [Info ] [Java] ...`，全局递增、线程安全，
  排查时直接说"看 #0042 那条"
- **TEMP 三档策略**：从不写入（默认） / 仅小文件 / 全部写入；可设 TEMP 总量上限、单文件上限，退出自动清理
- 游戏目录与其他启动器通用格式互通，可选写入 `launcher_profiles.json`
- 无任何遥测

### 在线更新

启动器按 `https://lpml.pages.dev/api/v1/lpml/` 拉取 `update.json` 与签名，**全部走 HTTPS**：

- 清单必须用内置的 **Ed25519 公钥验签**通过；整包还要与清单里的 **SHA-256** 一致。任何一步不过都不应用更新，也不替换任何文件。
- 只认 **`num` 严格大于本地已记录序号**的清单；更新完成后把新的 `num` / `id` 写回本地配置，不上传任何数据。
- `important`：`1` 必须更新（弹窗不能关，Esc / Alt+F4 也不放行）、`2` 重要更新、`3` 可选更新。设置里可屏蔽自动检查时的可选更新，手动检查仍能看到全部。
- 清单里两条下载地址都会尝试；弹窗里可选排序：自动按清单顺序 / GitHub 直连优先 / 代理线路优先，选中的先试、另一条作失败兜底。
- 更新包分**带 .NET 运行时**与**不带运行时**两种；默认按当前安装是否自带运行时自动匹配，也可在设置或弹窗里手动切换。手动切到不带运行时前，请确认目标机器装有 .NET 10。
- 中英文更新说明各指向一个 JSON，取其 `main` 字段作 Markdown 正文显示；说明拉取失败只影响展示，不阻断安全更新。
- 应用时：整包解压到 `LPML\cache\update-*` → 拉起暂存程序 → 替换根目录下的程序文件并启动新启动器 → 删除暂存目录。全程不碰 `LPML\` 里的配置、账户、日志与 `.minecraft\` 游戏数据；替换过程另记在 `LPML\logs\update.log`，失败按备份回滚。
- **设置 → 在线更新**：总开关、立即检查、屏蔽可选更新、下载线路、更新包类型、签名文件名，并显示当前更新序号与已应用版本；「启动时检查更新」在**设置 → 高级**。检查失败只提示，不阻止启动器继续使用。
- 验签只保证清单在传输中未被篡改，**不是运行授权**：程序本体不带签名，关闭更新或换掉端点后照常运行；强制更新只由 `num` 触发，不检测程序是否被修改。

#### 发布清单格式与自建更新源

`update.json` 用 snake_case，完整定义见 `src/LPML.Core/Update/UpdateModels.cs`：

| 字段 | 含义 |
|---|---|
| `name` / `id` | 更新名称与版本标识（`id` 必填） |
| `num` | 更新总顺序，正整数且严格递增 |
| `have` | `false` 表示服务端暂停推送 |
| `important` | 1 必须 / 2 重要 / 3 可选 |
| `have_runtime_down` / `have_runtime_sha256` | 带运行时整包的地址数组（两条线路）与 SHA-256 |
| `no_runtime_down` / `no_runtime_sha256` | 不带运行时整包的地址数组与 SHA-256 |

### 日志守护进程（子进程）
主进程启动后会用 `Process.Start` 再拉起**同一个 exe 的 `--guard` 实例**。因为是由主进程直接创建的子进程，
Windows 任务管理器的「进程」页会把两个 LPML 折叠在**同一组**里（父子进程树），而不是两个孤立条目。

- **不丢启动日志**：守护进程还没起来的那段，日志由主进程直接写 `lpml.log`。
  守护进程完成管道监听后回一个 READY，主进程先 Flush 本地文件，再把落盘目标整体切到命名管道 ——
  切换在日志锁内完成，切换瞬间的日志要么全在旧文件、要么全进管道，不会丢、不会写串。
- **接管之后**：所有日志帧（含异常堆栈里的换行，`BinaryWriter` 长度前缀传输）由守护进程统一写入同一个 `lpml.log`；
  界面仍从内存环形缓冲实时显示，两者互不干扰。
- **降级**：守护进程没起来 / 中途断开 / 启动失败，主进程会自动切回自己写文件，日志不会断。
- **看门狗**：心跳由 **UI 线程的 DispatcherTimer** 驱动，界面卡死时心跳自然停摆。
  超过阈值（默认 20 秒）守护进程会弹出提示「启动器已 N 秒没有响应，是否强制关闭？」；
  勾选「无响应时直接强制关闭」则不再询问，直接结束卡死的主进程。
- **不残留**：主进程正常退出、崩溃或被强制关闭，守护进程写完管道里最后的日志就自己退出。
- **设置**：设置 → 高级 → 启用日志守护进程 / 无响应判定时间 / 无响应时直接强制关闭（**下次启动生效**）。
- **启动参数**：`--no-guard` 本次不启用；`--guard-timeout=30` 改阈值；`--guard-auto-kill` 不询问直接关闭。
- 守护进程**不创建 WPF Application、不加载任何界面资源**，所以界面样式崩溃也不会拖累它；
  多开时按会话 GUID 隔离管道，互不串台。

## 🔑 微软登录与 Azure Client ID（合规必读）

LPML **不内置、不分发、不代管任何 Client ID**。启动器只提供一个输入框——你填什么，它就用什么。

### 为什么必须自备
微软的 OAuth 应用属于注册者本人。把他人注册的 Client ID 分发给第三方使用，违反
[Microsoft 服务协议](https://www.microsoft.com/servicesagreement)与 Azure 平台条款，
可能导致该应用被封禁。**本项目不接受、也不会内置任何共享 ID。**

### 三步获取你自己的 Client ID
1. 打开 [Azure 门户 → 应用注册](https://portal.azure.com/#blade/Microsoft_AAD_RegisteredApps/ApplicationsListBlade) → **新注册**
2. 填写：
   - 名称：任意（如 `LPML-Launcher`）
   - 支持的账户类型：**任何组织目录中的账户和个人 Microsoft 账户**
   - 重定向 URI：留空（设备代码流不需要）
3. 注册完成后：
   - 复制「应用程序(客户端) ID」
   - 左侧 **身份验证** → 高级设置 → **允许公共客户端流** → 设为 **是** → 保存
4. 把这段 ID 粘贴进 LPML：「账户 → 微软登录 → Client ID」

> 设备代码流（device code flow）是微软为「无法安全保存密钥的客户端」设计的公开客户端流程，
> 不需要 client secret，适合本地启动器这类场景。

### 不想注册？三条替代路径
| 方式 | 场景 | 说明 |
|---|---|---|
| **离线登录** | 单机 / 关闭正版验证的服务器 | 零配置，UUID 按官方离线规则生成 |
| **外置登录** | 自建 Yggdrasil 服务器 | 自动注入 authlib-injector |
| **LittleSkin** | 使用皮肤站 | 内置官方 API，自动注入皮肤 |

## ⚠️ 已知限制

1. **微软登录**需要你自己在 Azure 注册应用（勾选「允许公共客户端流」）并填写 Client ID —— **不使用他人 Client ID**，详见上一节。
2. **Forge / NeoForge** 安装通过官方 installer jar + Java 静默安装（`--installClient`），因此需要先有可用 Java。
3. **OptiFine** 官方安装器只有图形界面，启动器会下载并唤起它，由你点下一步完成。
4. **在线更新**依赖 `https://lpml.pages.dev/api/v1/lpml/` 可访问；清单未通过 Ed25519 验签、或整包 SHA-256 不符时不会应用任何更新。重要级别 1 的更新必须完成后才能继续使用。更新包默认按当前安装是否自带 .NET 运行时选择，可在设置或更新弹窗里手动切换。
5. Quilt 的镜像端地址沿用 Fabric Meta 兼容路径，若镜像未同步会回退官方源。
6. **BMCLAPI 偶尔不稳定**（403 / 429），遇到时会自动换源重试，不必手动干预；持续有问题可在设置里把默认源换成光速镜像或官方。
7. **本地库复用**的索引文件没有大小上限，装很多版本后会缓慢增长（索引本身很小，扫描靠大小+修改时间跳过未变动文件）。
8. **同时开多个启动器实例**会共用同一个 `lpml.log`（每次启动都会归档上一次），日志会混在一起；管道本身按会话隔离，不会串到别的进程，只是文件层面共用。
9. 守护进程设置（开关 / 阈值 / 自动关闭）在**启动时读取**，改完要重启启动器才生效。
10. **多人联机依赖陶瓦公共节点**，NAT 穿透失败时会退化到中继，延迟与稳定性不由本启动器控制；跨启动器互通取决于对方版本与网络，不保证成功。
