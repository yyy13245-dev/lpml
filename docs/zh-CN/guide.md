# LPML 使用说明

**LPML = Let's Play Minecraft Launcher**

一款用 .NET 10 + WPF 写的 Minecraft Java 版启动器。绿色便携：不写 C 盘、不写注册表、不写 AppData，整个目录拷到 U 盘就能带走。

---

## 一、第一次使用

> 第一次启动会先显示《用户协议与免责声明》。图形界面请完整阅读并点击「同意并继续」；命令行需输入 `是` / `我同意` / `同意` / `yes`。不同意请退出并删除本软件。协议可以在「文档」页随时重新查阅，命令行也可输入 `agreement` 重看。

1. **确认 Java**：启动器会自动扫描 PATH、JAVA_HOME 和常见安装目录里的 Java。
   一个都没有的话，去「下载 → Java 运行时」装一个，或到「设置 → Java 与内存」手动添加。
2. **安装游戏**：进入「下载 → 安装游戏」，在版本列表里**双击**一个版本。
3. **填写安装信息**：在弹出的页面里填保存名称、选加载器（不装加载器就选「原版」）、选实例文件夹。
4. **点「开始安装」**：右上角会出现「任务」按钮，点开可以看到实时进度。
5. **启动游戏**：回「开始游戏」页，选好实例，点右下角的启动按钮。

> MC 版本与 Java 的对应关系（装错了会跑不起来）：
> 1.16 及更早 → Java 8 ｜ 1.17 → 16 ｜ 1.18~1.19 → 17 ｜ 1.20+ → 21 ｜ 26w 快照 → 25

## 二、开始游戏页

- **实例**：下拉框选要玩的实例。没有实例时顶部会提示，设置面板也会整组置灰。
- **启动**：右下角按钮在任何页面都悬浮可见。在其他页面点它是跳到本页，在本页点它是直接启动。
- **静音**：一键把该实例的 `options.txt` 音量全部写 0。想恢复就在游戏里把音量调回来。
  已经是静音时按钮显示「已静音」并置灰。
- **多开**：可以同时启动多个实例。启动按钮始终用来启动，不会变成关闭按钮。
- **结束游戏**：有实例在跑时，右下角会多出「⏹ 结束游戏」。点开是一个小展开板，
  列出所有正在运行的实例，选中一个再点「结束所选」即可，不用去任务管理器里找。
- **实例下拉框**：新建的实例会立刻出现在下拉框里，直接选中就能切换，不用先去实例页点一遍。
- **日志区分**：几个游戏一起跑时，每条游戏输出前会带上实例名，不会混成一条流。

### 启动时要等多久

点启动后会弹出进度窗，**直到游戏真正进入主界面才关闭**：

| 阶段 | 在做什么 |
|---|---|
| ① 处理依赖 | 检查缺哪些文件，缺了就下载（显示数量、速度、剩余时间） |
| ② 正在登录 | 正版走微软验证、外置走皮肤站、离线直接通过 |
| ③ 准备启动 | 拼接 JVM 参数与 classpath |
| ④ 正在启动中 | Java 已运行，窗口里显示 MC 日志的最后几行 |
| ⑤ 关闭 | 检测到主界面日志（如 `Reloading ResourceManager`）才关 |

启动期间启动按钮、实例下拉框、静音按钮会一起置灰，结束后自动恢复。

## 三、下载中心

### 安装游戏

版本列表会显示状态（共多少个版本）。**双击版本**进入安装页：

- **保存名称**：安装后叫什么，也就是实例名。选了加载器会自动加后缀（`1.21.4` → `1.21.4-fabric`），
  **但你自己改过名字之后就不会再动它**。
- **加载器**：原版 / Fabric / Quilt / Forge / NeoForge / OptiFine。
  加载器版本列表按你选的 MC 版本拉取，不会出现版本对不上的情况。
- **实例文件夹**：装到哪个文件夹，默认 `.minecraft`。
- **名称重复会直接提示**，不用等装完才发现。

> 加载器不再单独占一个页面，直接在安装页里选就好。

### 整合包导入

- **本地文件**：支持 Modrinth `.mrpack`、HMCL / MultiMC / Prism 导出的 zip、通用 zip。
  CurseForge 包能导入框架和配置，但模组需要手动补（`manifest.json` 里没有下载地址）。
- **在线获取**：直接搜 Modrinth 上的整合包，按下载量排序。双击进入安装页后，
  可以依次选 **MC 版本 → 整合包版本 → 加载器**（加载器只能选作者提供的那些）。

### 下载模组

下载中心里有「下载模组」，实例的模组页里也有「⬇ 下载模组」按钮，进的是同一页。

- **安装到实例**：默认选中首页正在用的实例，也可以改选别的；模组会装到你选的那个实例的 `mods` 文件夹。
- **搜索**：输入名称后回车或点「搜索」，结果来自 Modrinth，按下载量排序。
- **版本**：点一个模组，右侧会列出全部可用版本，兼容当前实例版本与加载器的排在前面。
  勾选「按当前实例的加载器筛选…」时搜索只按加载器过滤，不会把本来兼容的整合包模组漏掉；
  整合包没写加载器时，会看已装模组里的 `fabric.mod.json` / `mods.toml` 来推断。
- **分页**：每页 20 个，用「上一页 / 下一页」可以翻完所有结果；看过的页会缓存，
  连续点下一页也不会瞬间向 Modrinth 打出一串请求。
- 点「下载并安装」后，文件会出现在任务中心的下载列表里，进度、速度、状态都能看到。

### 管理已装的模组

「实例 → 模组」里，每行末尾的小勾用来进入多选模式：

- 勾上任意一行，顶部会出现「全选 / 全部启用 / 全部停用 / 全部删除 / 取消多选」，
  并显示已选数量。批量删除会先确认一次。
- 「全选」点一次全选，再点变成「取消全选」，再点又变回「全选」。
- 单个模组可以右键选「删除这个模组」，也可以直接点行尾的「删除」。

### 下载失败怎么办

日志或任务里常见的两种错误：

| 错误 | 含义 | 处理 |
|---|---|---|
| **403 / 404** | 这个镜像没有该文件 | 会自动换源重试，最后回退官方地址。不用手动干预 |
| **429** | 请求太密被限流 | 自动退避等待；持续出现就把「设置 → 下载 → 并发任务数」调低（比如 12） |

BMCLAPI 偶尔不稳定属正常现象。想换个源：设置 → 下载源，可选官方 / BMCLAPI / 光速镜像。MCBBS 已停止服务，不再提供。

## 四、任务中心

右上角「任务」按钮：**有任务才出现**，没任务自动隐藏。点开是三级：

```
任务列表（一次操作 = 一个任务组）
  安装游戏            下载中 82/312
  ▓▓▓▓▓░░░░
      ↓ 点进去
详情 → 下载：先按大类汇总，每类一个进度条
  📦 整合包内容     312/640 个文件   ▓▓▓▓▓░░░
  🎮 原版内容       82/120 个文件   ▓▓▓▓▓▓░░
      ↓ 点其中一张卡片
  这一类里的每一个文件：名称、进度条、百分比、速度、状态
详情 → 安装：点开「安装流程」看全部步骤的流程图
```

安装整合包时，模组和原版游戏文件是混在同一次安装里的，所以分成两张卡片，
点进去才展开逐文件进度，几千个文件也不会挤成一屏。单独下模组或 Java 运行时时归到「其他文件」。

- **右键菜单**：任务组和单个文件都支持「重试 / 重新下载 / 取消下载」。
- 所有下载（模组、整合包、原版、Java）都汇总在这里。
- 完成后可用「清除」清掉，不会一直挂着。

## 五、实例与文件夹

### 实例文件夹

可以建任意多个文件夹，每个都是**一套完整的游戏目录**
（`versions / libraries / assets / mods / saves / config` 等）。

- 路径支持**绝对路径、相对路径（相对启动器根目录）、环境变量**（如 `%USERPROFILE%\...`）。
- 在「实例设置 → 文件夹」里可以：切换所属文件夹、直接指定目录、在该文件夹里安装游戏文件。
- 目录解析优先级：**直接指定 > 实例文件夹 > 隔离目录 > 默认 `.minecraft`**。

### 实例隔离

隔离数据放在 **`.minecraft\instances\<实例ID>\`**，跟着 `.minecraft` 走，整个目录拷走即迁移。

| 模式 | 版本文件 | mods / saves / config | 特点 |
|---|---|---|---|
| **仅用户数据**（默认） | `.minecraft`，多实例共享 | 实例目录 | 省空间 |
| **完整隔离** | 实例目录 | 实例目录 | 拷走即迁移，占空间 |

- 全局设置：设置 → 路径 → 隔离模式
- 单个实例可覆盖：实例设置 → 隔离（可选「跟随全局」）
- 两种模式之间可一键迁移，同卷走硬链接，不额外占空间

### 每个实例的 lpml.json

每个实例目录下会写一个 `lpml.json`，记录该实例的名称、版本、加载器、隔离模式。
跟着目录走——把实例目录拷给别人时，这些设置也一起过去。

## 六、账户

| 类型 | 说明 |
|---|---|
| **微软登录** | 设备代码流，自动刷新令牌。**需要自备 Azure Client ID**，启动器不内置 |
| **离线登录** | 零配置。可**自定义 UUID**：第 15 位（`3`）和第 20 位（`8/9/a/b`）是协议固定值会自动修正，其余 30 位随意改 |
| **外置登录** | 任意 Yggdrasil / authlib-injector 服务器，启动时自动注入 javaagent |
| **LittleSkin** | 内置官方 API 地址，开箱即用 |

**账户存放位置**：每个账户自己记着存在哪，可混用。

- 便携（默认）：`<根目录>\LPML\accounts\` — 不写系统盘，U 盘推荐
- 本机用户目录：`%USERPROFILE%\LPML\accounts\` — 换启动器目录也不丢
- 自定义：需先手动导入

## 七、设置

### 下载
- **并发任务数**：同时下载多少个文件，默认 32
- **按文件大小自适应并发**（默认开）：小文件多开、大文件收窄
  ```
  30 KB 库文件 → 48    2 MB 资源 → 32    5 MB 以上 → 8
  ```
- **平缓启动**（默认开）：并发从 4 个起、每 240ms 递增，1.7 秒爬满。
  避免瞬间几十个 TLS 握手卡住老机器、或被镜像判定为刷流量
- **单文件分段**：大文件拆成多段并行下载，默认 2 MB 以上启用、8 段
- 全局限速、代理、可选的「忽略证书错误」

### 下载源
三档可选：官方 / BMCLAPI / 光速镜像，还能按资源类型（17 类）分别指定。MCBBS 已停运，旧配置会自动改用 BMCLAPI。

### 目录与路径
游戏目录、缓存目录、隔离模式与迁移。

### Java 与内存
- Java 列表标明类型（`JDK 21 · Eclipse Temurin · 64位`）
- **启动失败自动换 Java 重试**：优先换同版本（JDK↔JRE），不会退到低版本
- 内存自动分配或手动指定

### 启动设置
- MC 窗口标题：走客户端原生 `--title`，要勾开关才生效
- 启动后行为：保持原状 / 最小化 / 退出
- 完整性检查与一键修复

### 外观
- **性能模式**（最上面一项，会覆盖下面的毛玻璃 / 模糊 / 动效）：
  - **标准**：完整观感 —— 毛玻璃 + 半透明卡片 + 补间动效
  - **流畅**：省资源 —— 卡片改不透明遮罩、关掉毛玻璃与背景模糊、
    悬停反馈在两个状态间**瞬时切换**（不做补间）、只保留页面淡入这一条动画、动图背景停在第一帧
  - 也可以用启动参数切换（**会写进配置，以后一直生效**）：
    ```
    LPML.exe --smooth     切到流畅模式
    LPML.exe --standard   切回标准模式
    ```
- **启动器标题**：改的是启动器自己的窗口标题，失焦即生效。留空恢复 `LPML`
- **背景图**：png / jpg / jpeg / bmp / **gif（可播放）**，可调透明度与填充方式
- 主题（深色 / 浅色 / 跟随系统）、强调色、动效开关

### 高级
界面语言（切换立即生效，无需重启）、日志级别、TEMP 策略。

## 八、命令行模式

带 `--cli` 参数启动时进入命令行模式，不创建窗口：

> 第一次使用（包括 `--list` / `--help` 等一次性查询）会先完整显示《用户协议与免责声明》。只有输入 `是` / `我同意` / `同意` / `yes` 才会继续；输入其他内容会直接退出命令行。同意状态与图形界面共用，记录在 `launcher.json`。

```
LPML.exe --cli [选项]

  --instance, -i <名称/ID>   指定实例
  --version,  -v <版本ID>    直接按版本启动
  --account,  -a <用户名>    指定账户
  --after <keep|hide|exit>   启动 MC 后的行为
  --list, ls                 列出实例
  --list-versions            列出已安装版本
  --help                     帮助
```

不带任何选项时进入**交互式 shell**，会单独打开一个控制台窗口，底部常驻提示只保留 `help`：
输入 `help` 查看完整命令表（约 50 条，覆盖实例、账户、版本安装、模组、下载、Java、设置与文档），
常用的有 `ls` 列实例、`launch <实例名>` 启动游戏、`quit` 退出、`clear` 清空日志区。

游戏启动成功后，同一个窗口接着变成**游戏 REPL**：上半区滚动显示游戏日志，底部输入行继续可用。
同一套命令仍可使用，输入 `help` 查看；未识别的输入原样转发给游戏进程。

`--list`、`--help` 这类一次性查询不会另开窗口，结果直接输出在当前 cmd 里，可以复制或重定向。
若输出被重定向到文件，交互界面会自动退化为普通的逐行输入。

## 九、目录结构

```
<根目录>\
  ├─ LPML.exe                 # 程序
  ├─ .minecraft\              # 游戏数据（PCL / HMCL / 官方启动器通用格式）
  │   ├─ versions\ libraries\ assets\ saves\ mods\ runtime\
  │   └─ instances\           # 实例隔离数据
  │        └─ <id>\ lpml.json
  └─ LPML\                    # 启动器自身数据
      ├─ config\              # 设置、实例、文件夹、库索引
      ├─ accounts\            # 账户（默认位置）
      ├─ cache\               # 分片临时文件、安装器
      ├─ backgrounds\         # 自定义背景图
      └─ logs\                # lpml.log + oldlog1~5.zip
```

**日志**：启动时若 `lpml.log` 有内容，会自动打包成 `oldlog1.zip` 并把旧归档后移，
最多保留 5 份（第 5 份最旧，超过就删除）。每条日志带编号 `[#0042]`，排查时说编号即可。

## 十、常见问题

**Q：点启动后提示找不到版本 JSON？**
通常是游戏目录被删了，或实例指向的目录不对。日志会写明查过哪个路径。
启动器会在其他已知目录里找同版本并自动复用（硬链接，不重下）。

**Q：提示「没有找到可用的 Java 0」？**
这是旧版本的误导性报错。现在会直接说明缺的是版本 JSON 还是客户端 jar。
若仍出现，把带编号的日志发来。

**Q：下载很慢？**
1. 点「设置 → 下载 → 应用推荐下载参数」
2. 把并发从 32 调到 12 左右试试（并发过高反而会被限流）
3. 换镜像源，光速镜像通常较稳

**Q：模组装到哪去了？**
实例隔离开启时，模组在该实例的 `mods` 目录（`.minecraft\instances\<id>\mods`）；
未开启时就在 `.minecraft\mods`。「实例设置 → 概览」有「打开模组目录」按钮。

**Q：能和其他启动器共用游戏目录吗？**
可以。游戏目录是官方标准结构，PCL / HMCL / 官方启动器通用。
还能在设置里添加它们的目录作为**库复用源**（只读），避免重复下载。

**Q：任务管理器里为什么有两个 LPML？**
一个是启动器，一个是它的日志守护进程（由启动器创建的子进程，所以显示在同一个分组里）。
守护进程负责把日志统一写到 `LPML\logs\lpml.log`；如果启动器界面卡死超过设定时间，
它会弹窗问你要不要强制关闭。启动器正常退出后它也会自己退出，不会留在后台。
不想要的话：设置 → 高级 → 关掉「启用日志守护进程」，下次启动生效。

## 十一、已知限制

1. 微软登录需自备 Azure Client ID（不内置、不代管任何他人的 ID）
2. Forge / NeoForge 通过官方 installer 静默安装，需要先有可用 Java
3. OptiFine 官方安装器只有图形界面，会唤起它由你手动点
4. CurseForge 整合包的模组需手动补（`manifest.json` 没有下载地址）
5. 「检查更新」目前未接入发行源
6. 守护进程的开关、无响应时间等设置要**重启启动器**才生效
7. 同时开多个启动器会共用同一个 `lpml.log`，日志会混在一起
